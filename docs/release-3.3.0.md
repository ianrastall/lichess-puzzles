# 3.3.0 validation

Validated on Windows x64, 30 October 2026. Application binaries were built from the working source committed as `359c83c` (bounded Rust engine screening). Subsequent release documentation changes do not affect compiled code. Development and publication use `main` directly.

- The normal installer build passed Rust formatting, Clippy with warnings denied, 58 Rust tests, 62 C# to native DLL integration checks, shared Jupiter style validation, WinUI publish, CLI publish, source packaging and Inno Setup compilation.
- The first parallel Rust test run failed two existing timing-sensitive service checks: download pause before a partial file existed, and a short-mate candidate batch timing out. Both passed in a separate serial service run and in the complete installer build with `RUST_TEST_THREADS=1`. No production budgets or test assertions were relaxed.
- Installed 3.3.0 over the existing per-user installation; installer exit code 0. Installed executable FileVersion is `3.3.0.0`, and its SHA256 matches the published application executable. The existing application-name Start Menu shortcut launched it successfully.
- Used an isolated verification profile with the full 6,157,341-record store. Visually inspected the unchecked default, checked experimental control and explanatory copy in the light theme. Disabled rated attempts for desktop checks. With exact mate-in-one/two screening and engine screening both enabled, Next opened puzzle `Fp0MZ`, rating 1500, within the fixed ±150 band around the local 1500 rating.
- The accepted puzzle had a complete cached engine review but first-turn agreement stabilized only from depth two, so it correctly failed the stricter shallow-agreement exclusion. This confirms that ordinary engine agreement alone does not reject a candidate. The UI showed zero rated puzzles throughout verification.
- Saved an `Engine screening check` preset with the new setting enabled and exact mate-in-one/two screening retained. Verified the serialized preset and current setting; closed and relaunched through the Start Menu and visually confirmed that the option remained enabled. Closed the verification window afterward.
- The normal profile's and earlier QA profile's `players.sqlite`, `puzzles.store`, `settings.json` and `ui.json` SHA256 values matched the fresh pre-install baseline. Their progress and settings were not migrated or overwritten. The new verification profile is separate. No test profile was left open for accidental training.
- No new dependencies or external engine process. Two 600-record sampled reviews, their selection controls, exact limits and timing measurements are documented in [engine-review.md](engine-review.md). The source store's SHA256 remained unchanged during these experiments. This is an experimental search-effort signal, not a calibrated human difficulty rating.
- The new control uses native shared styles and was visually checked in light theme. Dark theme and Windows contrast mode were not manually exercised for this release.

Release artifacts comprise the Windows installer, portable ZIP, complete source ZIP (including the exact Jupiter.UI snapshot) and SHA256 checksums. The source bundle is regenerated after final release documentation is committed.
